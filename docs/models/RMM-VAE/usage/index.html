How to Use

1. Environment Setup​

1.1 Get the Code​

Clone the project repository and navigate to the directory:

git clone https://github.com/jcarvoli/RMM-VAE_Euro_summer.git
cd RMM-VAE_Euro_summer

1.2 Python Environment​

The Python environment (rmm_env2) is installed inside the container described below.

1.3 Container​

To run the notebooks, we provide a container configuration file (.def) to build the container. The first time you use it, you'll need to build it and then bind it to a local folder.

  1. Navigate to the folder containing the .def file (for example, your Downloads folder):
cd ~/Downloads
  1. Build the container using the .def file:
singularity build rmm_env2.sif rmm_env2.def
note

Adjust the paths above to match where you've saved the project and the image on your own machine.

note

Once the build is done, move the .sif file to your project root directory for a simpler execution.

2. Configuration​

2.1 Configuration Files​

Paths and constants used throughout the notebooks are set in a single config.yaml file. Before running anything, update this file to match your local folder structure.

# config.yaml
paths:
  project_root: '<PROJECT_ROOT_PATH>'
  data_path: '<PROJECT_ROOT_PATH>/DATA'
  figs_path: '<PROJECT_ROOT_PATH>/figures'

constants:
  target_variable_name: 'var167'
  g0: 9.80665
  extended_summer_months: [6, 7, 8]
note

Make sure the paths in config.yaml point to the location where you saved the folders on your machine before running the notebooks. The config.yaml file is in the source directory of the project.

note

Feel free to set the paths as you wish, but we advise keeping everything inside the project root directory to make the reproduction more intuitive.

2.2 Parameter Reference​

FieldDescription
project_rootRoot folder of the project
data_pathFolder containing the input data
figs_pathFolder where generated figures will be saved
target_variable_nameName of the target variable used in the model
g0Gravitational constant (m/s²)
extended_summer_monthsMonths considered as "extended summer" (June, July, August)

3. Data Preparation​

Download and preprocess the data as described in Data, and place it in the folder set as data_path in config.yaml.

5. Outputs​

The figure notebooks save the figures in your project directory (figs_path). When run through the bash script in Figures and Tables, they also generate a new Jupyter notebook with all the cell outputs, so it is possible to check any desired cell output.

6. Figures and Tables​

6.1 Figures​

Running inside Jupyter​

Run the container, binding your local project folder to the /notebooks folder inside the image:

singularity run --bind <PROJECT_ROOT_PATH>:/notebooks rmm_env2.sif

Once the container starts, open the link it prints in your terminal to access the notebook interface. With this method, you'll be able to execute the notebooks cell by cell and make changes as you wish.

Bash scripts​

On an HPC system, all the paper steps can be run through a single batch script. To do so, build a bash script with the following commands. They will execute all the figure notebooks in sequence and generate all the figures and data used in the paper analysis.


module load singularity

export CARTOPY_DATA_DIR=<PROJECT_ROOT_PATH>/cartopy/shapefiles/natural_earth/10m/physical/ne_10m_coastline.*

singularity exec --nv rmm_env2.sif jupyter nbconvert --to notebook --execute Figure1_ERL_refactored.ipynb --output Figure1_ERL_refactored_out.ipynb --ExecutePreprocessor.timeout=-1

singularity exec --nv rmm_env2.sif jupyter nbconvert --to notebook --execute Figure2_ERL_refactored.ipynb --output Figure2_ERL_refactored_out.ipynb --ExecutePreprocessor.timeout=-1

singularity exec --nv rmm_env2.sif jupyter nbconvert --to notebook --execute Figure3_ERL_refactored.ipynb --output Figure3_ERL_refactored_out.ipynb --ExecutePreprocessor.timeout=-1

singularity exec --nv rmm_env2.sif jupyter nbconvert --to notebook --execute Figure4_ERL_refactored.ipynb --output Figure4_ERL_refactored_out.ipynb --ExecutePreprocessor.timeout=-1

singularity exec --nv rmm_env2.sif jupyter nbconvert --to notebook --execute Figure5_a_b_Table1_ERL_refactored.ipynb --output Figure5_a_b_Table1_ERL_refactored_out.ipynb --ExecutePreprocessor.timeout=-1

singularity exec --nv rmm_env2.sif jupyter nbconvert --to notebook --execute Figure5_c_d_ERL_refactored.ipynb --output Figure5_c_d_ERL_refactored_out.ipynb --ExecutePreprocessor.timeout=-1

note

Remember to adjust all the paths to your own system.
