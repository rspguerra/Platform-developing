Data-driven Seasonal Climate Predictions via Variational Inference and Transformers

Authors: Lluís Palma, Alejandro Peraza, David Civantos, Amanda Duarte, Stefano Materia, Ángel G. Muñoz, Jesús Peña-Izquierdo, Laia Romero, Albert Soret, Markus Donat.

Links: Original Paper | GitLab Repository

Scientific Objective​

The primary scientific objective of this work is to evaluate a novel, probabilistic deep learning approach for seasonal climate prediction. Unlike weather forecasts, which predict daily conditions, seasonal predictions focus on multi-month anomalies and face severe challenges with observational data scarcity and climate non-stationarity (regime shifts).

This project provides a framework designed to predict global three-month seasonal anomalies of temperature and precipitation throughout the year. To achieve this while avoiding the overfitting that plagues large machine learning models trained on limited observational records, the model is trained on vast climate model outputs. Crucially, the approach explicitly disentangles the predictability derived from long-term climate change trends from the predictability of natural, year-to-year (interannual) fluctuations during both training and validation.

Dataset and variables​

To overcome the limited temporal extent of observational datasets and expose the model to diverse climate regimes, the pipeline leverages a combination of simulated and real-world Earth system data:

  • Training Data (CMIP6): The model is trained on extensive General Circulation Model (GCM) outputs from the Coupled Model Intercomparison Project Phase 6. This provides thousands of simulated years, effectively increasing the sample size and preventing overfitting.

  • Validation Data (ERA5): The model's real-world predictive skill is validated against the European Centre for Medium-Range Weather Forecasts (ECMWF) 5th generation atmospheric reanalysis.

Input Features: The model ingests both global and regional fields to capture broad teleconnections and local dynamics. The primary variables utilized are:

  • tas: Surface Air Temperature

  • pr: Precipitation

  • tos: Sea Surface Temperature (Ocean thermal status)

  • zg: Geopotential Height (specifically at 500 hPa and 300 hPa)

Methodology​

The core architecture introduces an intrinsically probabilistic method to seasonal forecasting, utilizing a conditional Variational Autoencoder (cVAE) paired with spatial attention mechanisms.

  • Spatial Encoding: Two Vision Transformers (ViTs) process the complex spatial relationships and teleconnections within the input climate fields, compressing this information into a latent space representation.

  • Decoding: A Convolutional Neural Network (CNN) decoder takes this latent representation to reconstruct and predict the targeted climate anomalies.

  • Signal Decomposition: To address climate non-stationarity, the methodology strictly separates the climate change signal from stochastic variability:

    • Trend Extraction: A locally estimated scatterplot smoothing (LOESS) trend is regressed to isolate the long-term anthropogenic forcing.

    • Interannual Prediction: The cVAE model is explicitly tasked with predicting only the detrended, interannual fluctuations.

    • Model Assembling: The final probabilistic forecast is generated by recombining the cVAE's interannual prediction with the deterministic LOESS trend.

Evaluation​

All outputs are written under the experiment directory, whose path is defined by conf.exp_dir in paths.yml. A typical run produces the following structure:

exps/
└── <experiment_name>-<timestamp>/
    ├── train_loss_0.pkl
    ├── val_loss_0.pkl
    ├── loss_curves_0.png
    ├── loss_curves_by_term_0.png
    ├── models/
    │   └── <model_name>_0
    ├── output/
    │   ├── <model_name>_<var>_<dataset>_hcst_fcst.nc
    │   └── <model_name>_<var>_<dataset>_obs_fcst.nc
    └── imgs/
        └── <model_name>/
            └── metrics_<var>_<years>_<detrend>_fcst.png

train_loss_0.pkl / val_loss_0.pkl​

Serialised Python lists containing the training and validation loss values at each epoch. Load them with:

import pickle
with open("train_loss_0.pkl", "rb") as f:
    train_loss = pickle.load(f)  # list of floats, one per epoch

loss_curves_0.png​

Plot of training and validation loss over epochs.

loss_curves_by_term_0.png​

Same as above but broken down by individual loss terms.

models/<model_name>_0​

Saved PyTorch model state dict. This is the checkpoint loaded during the test phase. The filename suffix _0 corresponds to the training run index.

output/<model_name>_<var>_<dataset>_hcst_fcst.nc​

NetCDF file containing the model's hindcast predictions. Dimensions are (lon, lat, time, ensemble) — the model generates an ensemble of forecast_members=125 probabilistic predictions for each target year.

One file is produced per output variable (e.g. tas, pr, tos, zg500, zg300).

output/<model_name>_<var>_<dataset>_obs_fcst.nc​

NetCDF file containing the corresponding ERA5 observations, inverse-transformed to physical units. Used as the verification reference. Written only once per variable (subsequent runs with the same dataset skip writing if the file already exists).

imgs/<model_name>/metrics_<var>_<years>_<detrend>_fcst.png​

Verification metric plots. One image is produced per combination of:

  • variable (tas, pr, etc.)
  • verification period (1985-2021 or 2001-2021)
  • detrending (detrend or no_detrend)
